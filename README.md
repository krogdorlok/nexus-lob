# NexusLOB

[![CI](https://github.com/krogdorlok/nexus-lob/actions/workflows/ci.yml/badge.svg)](https://github.com/krogdorlok/nexus-lob/actions/workflows/ci.yml)

A C++20 limit order book and matching engine built for low, predictable latency: price-time
priority, zero heap allocation from order ingest to event emit, and a lock-free three-thread
pipeline. Every number below is generated by a script in this repo from files in `results/`.

* **Fast paths by construction.** Cache-line-sized orders in an intrusive FIFO, a flat price
  ladder with a two-level occupancy bitmap for best-price lookup, an open-addressing id index
  with backward-shift deletion, and a pre-faulted object pool.
* **Zero allocation, proven.** `test_no_alloc` replaces the global allocators with counting
  versions and runs a million mixed commands: zero allocations.
* **Correctness, proven.** An independently written `std::map`/`std::list` reference engine
  and a differential fuzzer that requires byte-identical event streams over 200 seeds x 100k
  commands, in CI, plus ASan, UBSan and TSan builds on GCC 13 and Clang 17.

## Architecture

```
 producer thread             engine thread (pinned)                publisher thread
+----------------+         +---------------------------+         +------------------+
| FlowGenerator  |  SPSC   | MatchingEngine            |  SPSC   | first event per  |
| stamp tsc on   | ------> |  OrderBook                | ------> | command: record  |
| push           | Command |   bids/asks: PriceLadder  |  Event  | tsc delta in a   |
+----------------+         |     PriceLevel (intrusive)|         | fixed histogram  |
                           |   OrderMap (id -> Order*) |         +------------------+
                           |   ObjectPool<Order>       |
                           +---------------------------+
```

| Component | File | Idea |
|---|---|---|
| `Order` | `include/nexus/core/order.hpp` | 64 bytes, `alignas(64)`, links inside the order |
| `PriceLevel` | `include/nexus/core/price_level.hpp` | intrusive doubly linked FIFO, O(1) unlink |
| `PriceLadder` | `include/nexus/container/price_ladder.hpp` | flat array per tick, best price from a 2-level bitmap |
| `OrderMap` | `include/nexus/container/order_map.hpp` | open addressing, linear probing, no tombstones |
| `ObjectPool` | `include/nexus/memory/object_pool.hpp` | preallocated, pre-faulted, LIFO reuse |
| `SPSCRingBuffer` | `include/nexus/queue/spsc_ring_buffer.hpp` | acquire/release, cached indices, padded |
| `MatchingEngine` | `include/nexus/core/matching_engine.hpp` | Limit/Market, GTC/IOC/FOK, cancel, modify |
| `NaiveEngine` | `reference/naive_engine.hpp` | the correctness oracle |

The matching rules (reject order, event contents, when modify keeps priority) are specified
once, at the top of [`include/nexus/core/events.hpp`](include/nexus/core/events.hpp).
[DESIGN.md](DESIGN.md) explains every decision and the alternative it beat.

## Build, test, benchmark

Requires CMake 3.20+, Ninja and a C++20 compiler (GCC 13+, Clang 17+, Apple Clang 17+).
GoogleTest and Google Benchmark are fetched at pinned versions.

```sh
cmake --preset release && cmake --build --preset release && ctest --preset release
cmake --preset asan    && cmake --build --preset asan    && ctest --preset asan   # ASan + UBSan
cmake --preset tsan    && cmake --build --preset tsan    && ctest --preset tsan

./build/release/fuzz_differential --seeds 200 --commands 100000   # full differential run
./build/release/nexus_lob --commands 2000000 --rate 1000000         # one pipeline run
scripts/bench_linux.sh                                              # regenerate results/ + table
```

Options: `NEXUS_NATIVE` (`-march=native`), `NEXUS_ASAN`, `NEXUS_TSAN`, `NEXUS_WERROR`.

## How latency is measured

**Latency** of a command is `tsc_end()` taken by the publisher immediately after it dequeues
that command's first event, minus the `tsc_begin()` stamp the producer wrote into the command
just before pushing it to the inbound queue. It covers both queue hops and matching. Ticks are
converted to nanoseconds with a ratio calibrated against `steady_clock` at startup.

Throughput comes from **flood** runs (the producer pushes as fast as the queues accept);
latency comes from **paced** runs on a fixed open-loop schedule, because flood latency only
measures queue depth. Recording uses a fixed-bucket histogram, so it allocates nothing.

## Limitations

* The committed results come from an Apple M2 laptop with a normal desktop session: no core
  pinning (macOS has no affinity API), no isolation, and a coarse system timer, so paced
  latencies are quantized to one tick and tails include OS noise. At the paced rate the
  median of both engines sits within a tick or two of the floor set by two cross-core queue
  hops, so end-to-end p50 on this machine does not separate the engines; the engine-only
  replay and the micro benchmarks do. Treat the e2e tail columns as a property of this
  machine, not of the engine, until rerun on an isolated Linux core.
* Hardware counters (`perf stat`) need Linux; they are TBD until run there.
* One instrument per engine, a fixed price band, no self-trade prevention, no iceberg, stop
  or pegged orders. The flow is synthetic, not a market data replay.

## Reproduce on Linux x86_64

On a quiet machine with `perf` (for example an AWS `c7i` instance):

```sh
sudo apt-get install -y cmake ninja-build g++-13 linux-tools-common linux-tools-$(uname -r)
sudo sysctl kernel.perf_event_paranoid=1     # allow perf stat without root
git clone https://github.com/krogdorlok/nexus-lob && cd nexus-lob
REPS=5 scripts/bench_linux.sh
```

The script builds with `-march=native`, runs every test, the full differential fuzz, the
micro benchmarks, single-threaded replay, the pipeline benchmark and `perf stat` for both
engines, then rewrites the results section above. For the lowest jitter, also boot with
`isolcpus=2 nohz_full=2` (the engine thread is pinned to CPU 2) and set the governor to
`performance`.
